# v5 — design spec (the "win" pass)

**Date:** 2026-05-17 (submission day)
**Budget:** ~4h
**Goal:** Apply the senior-PM critique. Cut what doesn't earn its place. Merge `/manager` into one action surface. Add the two dock-bay-respecting tech moves (fullscreen confirmation + 30s Undo). Promote the event log on asset detail. Rewrite the README in senior voice and flag a real bug.

This is the pass designed to win first place by applying the principle: **good UX taste is removing what's irrelevant, then doubling down on what's essential.**

## Goals

1. Subtract three features that don't earn their place (trend widget, mono code chips, ambiguity sub-line) — the "remove" half of taste.
2. Merge `/manager` + `/manager/reconcile` into one action-surface page. Drift cases as the primary view; directory secondary. `/manager/reconcile` redirects to `/manager`.
3. Add an Owner column to every drift row (Tech / Facilities / Procurement / Finance) so the manager knows who to delegate to at standup.
4. Close a classifier gap: add the "Missing from facilities" category for `in_service` assets with no facilities row.
5. Ship two persona-respecting tech UX moves: fullscreen scan confirmation (1.2s takeover) and a persistent "Last scan · Undo" strip with 30-second reversal window.
6. Promote the event log on `/manager/assets/[tag]` to the lede; demote metadata below the fold.
7. Add a Blocked-in-state band on `/manager` (received >24h, RMA >14d).
8. Rewrite the README in senior-PM tone, lead with subtraction, find and surface one real API inconsistency.

## Non-goals

- No new feature surfaces beyond what's listed.
- No motion / page transitions work.
- No mobile-specific breakpoints beyond Tailwind's responsive defaults.
- No optimistic UI / rollback (deferred — risky for the budget).
- No torch toggle on camera (deferred — mobile-only polish).

## 2. /manager merge — drift cases as primary, directory secondary

### Page architecture

`/manager` becomes the manager's primary morning page. Drift cases render as a compact, scannable list at top. The 1,012-asset directory becomes a collapsible "Browse all" section below.

`/manager/reconcile` redirects (`redirect("/manager")` from a route handler).

### Row shape

Each drift row has:
- **Severity bar** (left, 3px wide, color by tier) — red / amber / grey
- **Tag** (mono, bold, clickable → `/manager/assets/[tag]`)
- **Category label** (italic serif) — the existing 7 labels
- **Owner pill** (small chip) — tech / facilities / procurement / finance — clickable to filter the page to that owner's items
- **Age** (relative, mono small) — uses `card.age_days`
- Below the row: **three-system summary** (mono, one line: `ops X · fac Y · fin Z`)
- Below that: **action sentence** (sans, regular weight, with → prefix)

Compact but complete. No need to click through to see the drift detail.

### Owner column

| Category | Owner |
|---|---|
| `mislocated` | tech |
| `ghost_on_rack` | facilities |
| `orphan_on_rack` | tech |
| `missing_from_facilities` (new) | tech |
| `off_books` | procurement |
| `ghost_on_books` | procurement |
| `disposed_but_capitalized` | finance |
| `stale_rack_obs` | tech |

Click any owner pill in any row → filter the page to show only that owner's items (URL param: `?owner=tech`).

### Browse-all section

Below the drift cases, a collapsible `<details>` element labeled "Browse all 1,012 assets · 303 expected." When opened, it renders the existing `<ManagerFilters>` + asset table. State persisted via URL param `?expanded=true`.

### Sticky actions

`[📋 Copy for standup]` and `[🖨 Print]` buttons live in a sub-header bar that sticks below the global nav while the drift list is in view. Hide when only the browse-all section is in view.

### What `/manager/reconcile` becomes

A redirect:
```ts

  redirect("/manager");

```

The print binder layout that previously lived on `/manager/reconcile` moves to `/manager` (rendered only via `@media print`).

### New category: `missing_from_facilities`

Fires when `ops.state === "in_service"` AND no facilities row exists for the tag.

- Tier: **today** (operational urgency)
- Label: *"Missing from facilities"*
- Owner: **tech**
- Action: *"Re-scan store or deploy to fire the facilities write-back. If the rack is empty, the asset may have been moved without scanning."*
- Action color (severity bar): red

Implementation: add a check in `classify.ts` between the orphan check and the existing in_service mislocated check. The check is:

```ts
if (ops && !facilities && ops.state === "in_service") {
  return {
    category: "missing_from_facilities",
    tier: "today",
    asset_tag: tag,
    views: {
      ops: opsView(ops),
      facilities: null,
      finance: finance ? finView(finance) : null,
    },
    action: "Re-scan store or deploy to fire the facilities write-back. If the rack is empty, the asset may have been moved without scanning.",
    age_days: age,
  };
}
```

Type updates: add `"missing_from_facilities"` to the `DriftCategory` union. Add label to `labels.ts`. Test: add one classifier test for the new branch.

## 3. Tech UX — fullscreen scan confirmation + Undo strip

### `<ScanSuccessOverlay>` component

Fullscreen overlay that appears for 1.2s on successful scan commit.

**Visual:**
- `position: fixed; inset: 0; z-50` — covers everything including the global header
- Background: `bg-green-50/95` for success, `bg-red-50/95` for the error variant
- Centered content: large green-700 checkmark icon, "Stored" verb (or "Received" / "Deployed" / "Transferred"), the asset tag in 36px Plex Mono bold, model + serial below, action detail (→ location) below that, countdown text at the bottom (*"ready in 1.2s…"*)
- Tap anywhere = dismiss immediately

**Behavior:**
- Auto-dismisses after 1.2s using a `setTimeout` cleared on unmount
- On dismiss: input refocuses for the next scan
- Reduced motion: respect `prefers-reduced-motion: reduce` — no fade-in, just snap-show

**Files created:**
- `starter/components/scan/ScanSuccessOverlay.tsx`

**Where used:**
- The 4 tech pages render `<ScanSuccessOverlay asset={receipt} verb={verb} detail={detail} onDismiss={() => setReceipt(null)} />` whenever `receipt !== null`.

### `<LastScanStrip>` component

Always-visible strip below the scan input on tech pages.

**Visual:**
```
Last scan · C0009001 → stored · 8s ago         [↶ Undo]
```

- Compact, single line
- Reads the most recent successful entry from `useScanLog(scanType, userId)`
- Updates every second to refresh the "Xs ago" text
- After 30 seconds, the Undo button greys out (still visible, disabled)
- Hidden if scan log is empty

**Undo behavior:**

| Last scan type | Undo action |
|---|---|
| receive (new asset) | Not undoable — show "Receive can't be undone (assets aren't deleted)" on click |
| receive (duplicate) | Not undoable — same message |
| store (from received) | Not undoable in the strict sense; we POST `/api/scans/store` with the original location, logging an UNDO event. Notify: "Re-scan the asset to choose a different location." |
| store (from in_service, "de-rack") | Reversible: re-POST `/api/scans/deploy` with the prior rack location (we have it from the audit trail's `from_location`) |
| deploy | Reversible: POST `/api/scans/store` with the asset's pre-deploy location (also from `from_location` on the most-recent deploy event) |
| transfer | Reversible: POST `/api/scans/transfer` with `to_custodian` swapped back to the prior custodian |

Each undo emits a scan with `scan_payload="UNDO|<original-payload>"` so the audit trail records the reversal explicitly.

**Files created:**
- `starter/components/scan/LastScanStrip.tsx`
- `starter/lib/scan-undo/use-scan-undo.ts`

**The hook signature:**

```ts
function useScanUndo(scanType: ScanType, userId: string): {
  lastEntry: ScanLogEntry | null;
  available: boolean;          // true if reversible AND within 30s
  expiresIn: number;            // seconds until 30s window closes; null if no entry
  undo: () => Promise<void>;
}
```

The hook fetches the most-recent event for the asset to get the `from_state` / `from_location`, so the undo can call the right reverse-direction scan endpoint.

**Where used:**
- The 4 tech pages render `<LastScanStrip />` just below the `<ScanInput>`.

### Why this is a taste signal

The brief asks directly: *"What's the recovery path when the tech messes up?"* The Undo strip is the literal answer. Combined with the fullscreen confirmation, it's the most persona-respecting move in the entire submission.

## 4. Asset detail: event log as lede

### Layout

Current:
```
[Header card: tag, state pill, model, serial, location, custodian]
[Three-system snapshot]
[Procurement note]
[Event timeline]
```

New:
```
[PageHeader: crumb · tag (mono) · model · serial]
[Compact state strip: state pill · current custodian · current location]
[Procurement note, if present]

EVENT HISTORY (N events)            ← lede
[Event timeline, full]

────────────────────────────────────
DETAILS                              ← below the fold
[Three-system snapshot]
[Compact metadata: asset_class, parent_asset_tag, dates]
```

### Why

The brief says *"the event log is the manager's main forensic tool — surface it well."* Most candidates put the metadata first because it's what they have. We invert that.

### Implementation

- `starter/app/manager/assets/[tag]/page.tsx` — reorder JSX:
  1. PageHeader (existing)
  2. Compact state strip (new — replaces the header card)
  3. Procurement note (existing — keep position)
  4. Event timeline (existing — moved up)
  5. Three-system snapshot (existing — moved down)
  6. Metadata block (new — dl-style key/value pairs)

The compact state strip replaces the bulky header card and shows:
*[in_service badge] · held by tech-jane · at Bay-12 / B-04 / P-02 · updated 4mo ago*

One line. Mono for the location string.

1. **Lead** — live URL, Loom URL, spec/plan links

7. **What I'd build next (ordered)** — three items, each with a reason for being below the cut line today:
   - Bulk re-import for end-of-quarter audit
   - Service-worker offline scan queue
   - Acknowledge / snooze persistence on drift
8. **Repo layout** — brief tree

### Tone

Match the brief's tone — sharp, specific, no hedge words ("possibly", "maybe", "I think"). Every sentence either asserts or commits.

## Risk register

| Risk | Mitigation |
|---|---|
| Removing trend widget breaks the reconcile page render | Search for all imports of TrendWidget before deletion; remove cleanly. |
| Undo logic for store/deploy uses asset's `from_state` which requires an event lookup | Hook fetches `/v1/assets/:tag/events` for the latest event of the matching type. One GET per undo. Acceptable. |
| Fullscreen overlay hides the global header | Intentional. Auto-dismisses; tap-to-dismiss. Z-50 above everything. |
| /manager redesign breaks existing /manager URL params (?state=, ?site=, ?q=) | Keep URL param handling in the browse-all section; preserve the existing filter logic. |
| Removing CATEGORY_CODE breaks format-standup tests | Tests need updating; one assertion change. |
| The receive→deploy state transition for "Undo store" may fail if the asset is currently in 'stored' state and was originally 'received' (not in_service) | The undo strip should communicate non-reversibility clearly: "Receive can't be undone." We don't synthesize fake reversals. |
